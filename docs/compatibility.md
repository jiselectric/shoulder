# Compatibility: alpha.17

## Verified environment

macOS, Node 22.22.2 (with historical Node 20.0.0 evidence), Codex 0.163.0 and tmux 3.6a. Node 22+ and tmux 3.6a+ are required. Doctor rejects older tmux versions before launch. The minimum covers the selection-position option introduced in 3.6 and the pane-border divider resize correction in 3.6a ([upstream changelog](https://github.com/tmux/tmux/blob/master/CHANGES)). Linux wrapper/terminal/package acceptance passes in a Debian container with Node 22.23.3, tmux 3.6a and a UTF-8 locale. Native authenticated Codex acceptance was performed on macOS only. Native Windows is unsupported by the tmux runtime.

Launch from an interactive UTF-8 outer terminal, outside another tmux session. On Linux, use a UTF-8 locale such as `LANG=C.UTF-8`; an ASCII-only locale can make tmux diagnostic output replace Unicode characters with underscores. Mouse reporting must reach tmux; Apple Terminal exposes View → Allow Mouse Reporting. The private tmux server captures direct pane drags for selection, even when the native CLI requests mouse events. Ordinary keys remain native when there is no selection. Click or Escape leaves selection mode and restores native typing, including rapid SecondClick events. The numeric copy-mode position indicator is replaced by a selection hint. Repeated backward/multiline drags across both panes are tested in emacs/vi key modes. Divider dragging resizes; the footer exposes Open side before creation, then Close/Reopen side, alongside Clear side. Each invocation uses its own socket/config without changing shared tmux settings. Scroll events select the pointer’s pane before forwarding native mouse input; they never synthesize Up/Down history keys. Native hover focus is enabled only when tmux exposes `focus-follows-mouse` (newer than the tested 3.6a floor). On 3.6a, scrolling/clicking establishes focus. If the outer terminal converts wheel gestures to keyboard arrows rather than reporting mouse coordinates, Shoulder cannot distinguish those from intentional history keys; enable mouse reporting in that terminal. Pure hover support on newer tmux is capability-probed but not covered by the current 3.6a runtime acceptance.

## Main command passthrough

`shoulder EXECUTABLE [native arguments]` forwards native tokens in order, with no native argument allowlist. Wrapper options before `--` are `--session UUID`, `--side-model MODEL`, `--side-effort EFFORT`, `--provider codex|claude|generic`, `--no-banner`, and `--no-direct-keys`. Everything after `--` is native. Native flags, permission modes, positional prompts, paths containing spaces, and shell-sensitive characters are passed as argv, not shell source. Aliases/functions need an executable wrapper script.

Codex interactive launches receive an invocation-local footer configuration so the current conversation can be identified. Added flags precede a native positional `--`. Interactive native resume/fork commands retain their tokens and receive the footer too; main native fork identity is read from the UI, never assumed to equal its parent. Noninteractive commands receive no injected footer where recognized.

Native flags are validated by the installed native CLI. Main launch accepts flags that the fork adapter does not yet understand. In that case only the side action fails, explicitly naming the unsupported side option.

## Codex clean side behavior

- The main's current UUID is parsed from the supported native footer and verified against exactly one saved local session. No UUID search in response text or newest-file heuristic is used.
- Completed source model, effort and cwd are read from saved metadata. Incomplete/active/ambiguous source sessions block forking. Explicit model and effort fallback requires a verified completed source cwd.
- Sides start as fresh `codex` sessions without a positional question or replayed history. A `developer_instructions` override contains the exact source UUID/path and requires a fresh read of completed main user/assistant messages before every side reply, including later appended turns. Recent bounded retrieval and older relevant search are model guidance, not wrapper-enforced tool limits or guaranteed synchronization. This replaces any configured developer-instructions value in the side only; built-in/project instructions and the main remain native. Original permission/profile/config switches understood by the adapter are preserved; main prompt/session identity tokens are not copied as new side prompts. Explicit current model/effort and a session footer are added. No forced read-only override is applied.
- Context follows the linked source UUID. Native main `/new` changes that UUID; select a passage again to rebind a side. Existing live sides retain their startup policy after an upgrade until recreated; Close/Reopen does not update it. Refresh should ignore unfinished turns/partial tail records and report inability to establish fresh context. Historical source requests are data, not new side authorization. Refresh can add tool latency, input tokens and provider exposure on each submitted side question.
- Native idle input is recognized before quoted source is bracketed-pasted as a draft, with no Enter. Editing may hide the normal shortcuts hint or show `tab to queue message`; the native composer and UUID footer remain required. Exact saved lifecycle is checked before buffering and again before paste. A fresh prompt-free side has no saved file until its first submitted turn. This is allowed only for a wrapper-created unsaved side with an unchanged verified UUID, and ends once saved metadata is observed. Partial, active, conflicting or malformed records still block insertion. Known native world-state/token-accounting records are validated without relaxing turn lifecycle checks.
- Subsequent selections append to the side's input at its cursor, retaining unsent text. Busy views and trust/approval dialogs receive no input. Source and side identities are checked on each action.
- Native side `/clear` identity changes cause a new clean side referencing the current main on the next selection. Wrapper Clear starts a fresh native conversation in the same pane, keeping its size/focus and the source reference/settings; Close hides the live pane in a detached window of the private runtime, retaining history, drafts and any running turn. Reopen restores that same process and its previous width (clamped to fit a resized terminal) without sending input. Selecting another passage from the same main also restores it; a different main UUID starts a new source-linked side. Clear while hidden restores the pane and replaces its chat. Preservation ends when the wrapper exits or the native side process quits. Clear also works while the main is answering because it reuses the validated side launch settings. Replaced UUIDs are rejected until fresh input is observed, including after repeated Clear clicks. Neither permanently deletes saved histories.
- Native configuration and session UI versions can change. Unknown footer/lifecycle shapes fail with a local compatibility message instead of guessing context or injecting into another view.

## Claude and other executables

Claude launches and native arguments are supported. Fresh interactive launches can receive an exact invocation session ID. Exact UUID resumes and fork arguments are available; named resumes/continue run natively but require a resolved exact identity for wrapper context actions. Explicit fork child IDs take precedence over their resume parent when tracking identity.

The Claude adapter reads only the exact session's saved metadata for model, effort, directory and completion. Permission flags with multiple values retain all values. It never chooses a session by timestamp. Native input readiness has not been verified because the local test stopped at a separate project trust prompt. Automatic Claude quote insertion is therefore disabled. Side selection refuses immediately with an unsupported-feature message before scanning metadata or creating a pane. Claude is main launch only in this candidate.

Generic executables can launch with their arguments unchanged. Only tmux is a structural dependency; native launch errors remain native. No contextual fork is offered without a provider adapter. Supporting an executable does not imply that it exposes a resumable conversation or supports a compatible native UI.

## Data and performance

Selection size is bounded to 16 KiB UTF-8; terminal controls are sanitized. Generated private files/buffers are cleaned after staging; quote bytes never become tmux shell commands. Explicit bracketed input avoids tmux's conditional paste mode falling back to raw newlines. Model requests only begin through user submission in the native CLI.

Saved provider history and authentication are managed by the native CLI. Fork history may persist, and close/reset does not erase it. The wrapper does not read authentication tokens or write provider/global terminal settings. Side permission behavior follows the original CLI flags and configuration.

Main output uses inherited native stdio and tmux directly. Wrapper metadata scans and readiness checks run on side actions; the side is instructed to invoke its local context reader before each reply. Neither runs on every output token. Startup, rendering and concurrent model work have costs; no zero-overhead or identical-generation guarantee is claimed. See verification for bounded local measurements and actual native evidence.


## Header and direct keys

The left-aligned header shares the terminal with immediate native input; it has no Enter gate. A quiet row with the pane name separates the expanded header from chat. Small terminals collapse it. `--no-banner` starts with compact bottom controls; the Hide/Show buttons or `Ctrl-b` then `b` toggle visibility for this invocation without restarting chats.

Codex binds Ctrl+backslash to focus the next visible pane and Ctrl+Q to open a blank context-linked side, or close/reopen an existing side directly. Opening waits for a completed saved main turn and a verified native side composer; it stages no quote or prompt and submits nothing. Reopening preserves the same live process and draft. Prefix alternatives remain: Ctrl-b then lowercase o/x/c/b for focus, side toggle, clear, and banner. `--no-direct-keys` disables the direct chords and updates header hints. The managed tmux client uses raw input; acceptance checks cover actual control-byte routing. These are not a guarantee against a terminal emulator or custom native configuration intercepting the same keys. No terminal/OS preferences are changed, and native Windows execution is unsupported.

Selection forwarding uses copy-pipe with both clipboard and paste-buffer creation suppressed, including rejected selections. It preserves unrelated existing tmux buffers. The separate temporary named buffer used for bracketed staging is deleted after the operation. Helper diagnostics are rendered as literal text, avoiding tmux format expansion of native option names.

## Rejected controls

Before the first completed saved main answer, Open side shows a brief prerequisite message and leaves native input usable. Active, malformed, unsupported or unavailable source context still fails closed; an expected refusal does not open a tmux helper-output view. Native main/side process failures and fatal bootstrap errors retain their error handling.

## Incremental context reader (alpha.17)

Native sides are instructed to invoke the shipped read-only reader before each reply. First use or recovery after compaction returns recent completed text; later calls pass the returned checkpoint for deltas or an unchanged receipt. Earlier messages remain available through literal search and indexed paging. Search and older-message reads return no refresh checkpoint. Output is capped at 12,288 serialized JSON bytes by default (programmatic bounds 1,024–32,768); large messages require continuation. Source scans are bounded at 256 MiB, 1 MiB per record and 100,000 complete records. Exact source identity, completed lifecycles, canonical-message deduplication, no-follow file opening and coherent-scan checks fail closed on unsupported data. Active/aborted text is omitted; a trailing incomplete line is reported without treating it as completed content.

Offsets use UTF-16 code units with safe Unicode splitting. Checkpoints bind source path/session and consumed-prefix fingerprints. Rewritten consumed history resets to a recent snapshot; malformed or foreign checkpoints reject. Checkpoints live in native side tool history, not a new on-disk transcript cache. Invocation/tool permissions and recall remain model-dependent; arbitrary raw native reads are outside reader bounds. Delta output reduces repetition and does not guarantee billed-token savings or complete model recall. Existing sides need recreation after upgrading.
