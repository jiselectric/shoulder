# Shoulder verification: 0.1.0-alpha.17

October 19, 2026, America/Los_Angeles. This record covers the prepared MIT-licensed `shldr` alpha candidate. It does not assert that npm publication has occurred. Source-only audit reports and temporary terminal logs are excluded from the package.

## Alpha.17 incremental context reader

Alpha.17 adds a read-only local reader and changes the side retrieval policy. The first read returns recent completed user/assistant text; later explicit checkpoints return new messages or a small unchanged response. Literal older search and exact-message paging remain available, including paged search results. Filtering and checkpoint validation require no model call, transcript copy, mutable consumption file, additional dependency or permission override. Complete serialized JSON is bounded at 12,288 bytes by default; pagination preserves oversized text. Read-only coherent scans reject unsupported/ambiguous records or concurrent source changes; they cannot establish an atomic snapshot extending through the model reply.

The new parser/CLI/policy and evidence-validator tests cover canonical deduplication, lifecycle/identity ambiguity, active/aborted/partial records, UTF-8, output escaping/budgets, large-message and search pagination, repeatable cursors, source rewrites, foreign cursors, hard limits, old-message retrieval, symlink invocation, and exact shell-quoted commands under hostile installation/source paths. Independent review found contradictory secondary identity and orphan context gaps in the initial implementation; both were reproduced and fixed before native acceptance. A CLI symlink entrypoint failure was also reproduced and fixed. No existing pane/input or permission guard was relaxed.

The final alpha.17 macOS and unprivileged offline Linux gates each passed **222/222 tests**, zero failures/cancellations/skips, plus typecheck, installed-package smoke, both benchmarks and the exact **36-file** inventory. Package smoke exercises the installed local reader under a path with spaces, including snapshot and unchanged results. Linux mounted only 64 curated public source files and locked development dependencies, with network disabled; the first container start found Docker stopped and is not acceptance evidence. Starting the existing local QA daemon allowed the unchanged run to pass.

Two native six-turn cases passed: both unhinted new-value answers read the exact source on the same side, an intervening unchanged follow-up invoked the reader with its preceding checkpoint and returned no message text, and the later update used a delta containing no previous value. Parent bytes stayed unchanged during side operations; Clear retained pane/width and changed native identity. The final reader responses were **2,278 bytes (snapshot, 5 messages)**, **518 bytes (unchanged, 0 messages)** and **910 bytes (delta, 2 messages)**. Fresh-value side turns each used one tool call and took 5.471 / 4.365 seconds; the unchanged turn took 5.098 seconds. These are observed native behavior and whole-turn timings, not a universal freshness or speed guarantee. The two cases made 12 explicit QA model turns in total; their normal provider histories remain saved. The harness additionally records native token-counter differences when available, without treating them as a controlled billing comparison.

The reproducible fixed-source benchmark compares 24 refreshes of the same bounded recent reader without a checkpoint against one snapshot followed by checkpoint deltas/unchanged receipts. With 120 initial turns and 3 appended turns, it returned 232,176 versus 23,908 serialized response bytes (**89.70% less**), 576 versus 30 message fragments, and 20 unchanged receipts. Median local reader time was 1.761 ms on macOS and 1.670 ms on Linux for the 307,755-byte synthetic source. This isolates repeated retrieval output; it excludes policy-prompt overhead, native tool choices, tokenizer counts, provider caching/prices and billed savings. Each refresh still scans the bounded exact source locally; there is no persistent transcript cache. Neither the byte comparison nor observed token counters prove a percentage reduction in total billed tokens.

An independent review also passed 100 mixed Unicode/control/escape cases across 298 refresh pages and 227 older-message pages, then 40 search cases across 1,068 search pages and 87 older-message pages with all 1,228 matching indices exactly once. The search property run used local Node 20; authoritative platform gates use supported Node 22. A property-test oracle initially counted only generated marker matches instead of all literal substring matches, then was corrected without changing production code. Identity/orphan/symlink and search-continuation regressions were observed failing before fixes. All remaining native/terminal, permission, model-guidance and earlier unexplained stress limits below remain applicable; alpha.16 evidence is historical.

Alpha.17 terminal stress passed **100 lifecycle cycles** in 74.097 seconds (300 quote stages, 100 unsent drafts, 101 closes, 100 reopens/Clears/selections, 20 narrow refusal/recovery pairs), with all 205 observed processes gone and the runtime removed. The header harness passed **50 cycles** in 77.965 seconds (100 focus/side/banner changes, 50 Clears/selections, 100 resizes), with all 52 providers gone and runtime removal. Neither made a model request or unexpected submission. These runs do not resolve the separate historical alpha.14 timeout below.

## Authenticated live-context retrieval

Alpha.13's earlier two-turn verification explicitly told the side to read its source. That proved access, not ordinary conversational freshness. A later five-turn baseline reproduced a stale second answer: the side read the first new main number, then reused it after another main update with no new tool read. Alpha.13 must not be published as the corrected candidate.

The policy now requires a fresh read of completed main user/assistant messages before each side reply. `npm run verify:context` makes **five authenticated native turns**: finish a neutral main turn, open the side, finish a new unpredictable main number, ask an unhinted side question, update the main again and ask the same side a “now” follow-up. Side questions contain no main/source/read/transcript hint or hidden answer. Each answer must include a matching exact-source tool read in its own completed turn, fresh value absent from all earlier side input, the exact new answer, unchanged parent bytes during that side operation, and the same saved side UUID. Old/cross-turn reads, stale answers, hinted questions, side replacement and parent changes are rejected. Clear also retains pane/width and changes identity.

**Two independent native runs passed all four fresh-answer checks**, with Codex 0.163.0, model `gpt-6.1-sol` / `high`. Every side answer used one tool call. Serialized tool-output sizes were 6,194 / 3,130 bytes and 5,366 / 1,994 bytes; observed side-turn times were 6.479 / 8.124 seconds and 8.466 / 6.221 seconds. These are whole-turn local observations, not isolated retrieval overhead, token counts or a maximum latency guarantee. Neither parent's bytes changed during its side operations. The same-side and Clear checks passed in both runs. The strengthened validator also rejected the actual saved stale baseline trace. A third five-turn case used the actual public CLI in an attached terminal with `codex --yolo` and no `--no-daemon`. Real copy-mode selection plus `e` opened the side before either number existed. Both unhinted answers passed the same fresh-read/value/identity/parent checks. They used one tool call each, 1,516 / 1,397 serialized output bytes, and took 6.801 / 4.471 seconds. Public native `/quit` returned zero; owned runtimes/frontends were cleaned without stopping shared native services.

Saved completion can precede native TUI repaint. An initial revised harness attempt stopped at a missing composer footer; the harness now waits read-only for the exact normal composer identity before a single submission. Questions are not retried and per-turn evidence assertions are unchanged.

This is model/tool guidance, not wrapper-enforced synchronization. Native permissions can block reads; the model should state that limitation. Refresh adds side-response work and provider exposure on every submitted side question, even if the question seems unrelated. Prompt guidance asks for bounded recent reads and relevant older search, but wrapper parser limits do not constrain arbitrary native tools. A source can change during a read. The link follows one original source UUID; after main `/new`, a new selection rebinds it. Existing live sides keep their old policy until recreated. Provider QA histories from the explicit tests remain saved. Ordinary tests, smoke, doctor and deterministic benchmarks make no model requests.

## Security and privacy findings

Independent reviewers reproduced and verified fixes for these issues:

- **Quote retention:** copy-mode forwarding also created an automatic tmux paste buffer. The action now uses `copy-pipe-and-cancel -CP`, suppressing clipboard and paste-buffer creation at the source, including rejected selections. Actual emacs/vi tests prove that no quote buffer remains and unrelated existing buffers are preserved through Close/Clear.
- **Diagnostic integrity:** unsupported native option names in helper errors could be expanded as tmux formats. Both helper error branches now use `display-message -l`; independent probes verify literal format-looking text. Shell execution was not demonstrated by the original diagnostic probe.
- **Shutdown reliability:** a late native outcome writer could race removal of its private result directory and turn intentional detach into a launcher crash. Bounded filesystem retries handle that finite write/rename race; the regression exercises the actual OS error and checks successful detach and directory removal. This was an availability/cleanup issue, with no demonstrated privilege or socket-scope escape.

The preceding alpha.13 security/privacy validation passed 42 and 40 focused checks. Alpha.14 changes only the side context policy; an independent review checked its completed-turn, historical-data, permissions, privacy and cost boundaries and corresponding public disclosures. Its native evidence and integrated gates are recorded above. Reviews also covered native argv, tmux command/format/shell interpretation, private file modes, parser bounds, exact identities, lifecycle races, inherited permissions, no implicit submission, no direct network/telemetry path, retention disclosures and scoped cleanup. Selected passages never become shell source or native launch argv.

This is evidence about the reviewed code and observed tests, not a universal security certification. Native tools/permissions, provider retention, same-account/admin access, abrupt SIGKILL/machine failure and disk snapshots remain outside the private-resource guarantees. See [security](../SECURITY.md), [privacy](../PRIVACY.md), [compatibility](compatibility.md) and [release instructions](release.md).

## Performance scope

A local equal-geometry five-pair experiment observed 38.141 ms median direct readiness versus 70.530 ms wrapped readiness (32.389 ms difference). It measures headless `createRuntime` setup/process startup with a fixed local provider. It excludes doctor, attached-client paint, authentication, network/model latency, token use and human input, and is not a universal overhead guarantee. Main output still uses native stdio. Wrapper metadata scans occur on side actions; the side model is instructed to refresh source context on each submitted side turn, with additional tool/input cost, not on every output token. README images are documentation assets and are not loaded into the live terminal.
